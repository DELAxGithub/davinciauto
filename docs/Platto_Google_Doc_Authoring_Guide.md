# Platto Google Doc Authoring Guide

更新日: 2026-06-20

## 目的

EP40以降のプラっと編集で、Google Docを人間にも読みやすく、DaVinci Resolveへの自動反映にも使いやすい形で書くためのマニュアル。

目標は、台本の自由度を消すことではない。機械が読む欄と、人間が読む欄を分けることで、Docから以下を自動生成しやすくする。

- Resolveマーカー
- 残し/カット/復活のIR
- 新規タイムライン案
- ナレーションWAV生成リスト
- ナレーション配置案
- 限界レポート

## 基本ルール

Google Docは、本文パートと表パートに分ける。

- 本文パート: 構成意図、SEG説明、演出メモ、迷ったときの判断基準を書く。
- 表パート: 機械が読む正本。Resolveへ反映したい編集判断は必ず表に書く。

自然文の見出しや段落は、人間向けメモとして自由に書いてよい。ただし、機械が確実に読むのは表だけにする。

## 必須表

発話素材の表は、最低限この5列を持つ。

| 編集指示 | Speaker Name | イン点 | アウト点 | 文字起こし |
| --- | --- | --- | --- | --- |
| KEEP | 木崎 | 00:02:11:20 | 00:02:18:05 | 京都大学の先生と話す機会なんてないんで... |
| CUT | 朴 | 00:03:07:17 | 00:03:09:23 | テレビないんですか? |

列名はできるだけ固定する。特に以下は変えない。

- `編集指示`
- `Speaker Name`
- `イン点`
- `アウト点`
- `文字起こし`

CSV由来で `色選択` がある場合は残してよい。ただし、`色選択` は補助情報であり、最終判断は `編集指示` を優先する。

## 推奨列

もう一段自動化したい場合は、以下の列を足す。

| 列名 | 目的 |
| --- | --- |
| `配置先` | `main`, `ending`, `narration`, `broll` など |
| `優先度` | `A`, `B`, `C`。45分へ戻すときの採用順 |
| `自動化レベル` | `AUTO`, `SEMI`, `MANUAL` |
| `備考` | 人間向け補足。配置ロジックには直接使わない |

例:

| 編集指示 | Speaker Name | イン点 | アウト点 | 文字起こし | 配置先 | 優先度 | 自動化レベル | 備考 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| RESTORE | 朴 | 00:18:44:03 | 00:19:24:03 | 各アパートに共用サウナ... | main | A | AUTO | サウナ復活 |
| MOVE_AFTER:NA12 | 木崎 | 01:12:17:03 | 01:12:29:09 | 異分野と話すと視野が広がる... | ending | A | AUTO | 締めcouplet |
| KEEP | 朴 | 00:57:16:08 | 00:57:30:20 | 入管法以降は在留カードを... | main | B | SEMI | 要点だけ使う |

## 編集指示タグ

`編集指示` 列は、できるだけ以下のタグで始める。

| タグ | 意味 | 自動化 |
| --- | --- | --- |
| `KEEP` | 残す | 自動配置可能 |
| `CUT` | 落とす | 自動カット候補 |
| `RESTORE` | 復活させる | 自動配置可能 |
| `MOVE_AFTER:<ID>` | 指定位置の後ろへ移動 | 自動配置候補 |
| `MOVE_BEFORE:<ID>` | 指定位置の前へ移動 | 自動配置候補 |
| `TRIM_HEAD:<timecode>` | 頭を指定量/指定点まで詰める | 半自動 |
| `TRIM_TAIL:<timecode>` | 尾を指定量/指定点まで詰める | 半自動 |
| `NA_INSERT:<NA ID>` | ナレーションを挿入 | WAV生成/配置候補 |
| `NA_DELETE` | 既存ナレーションを削除 | 半自動 |
| `NOTE:` | 人間向けメモ | 自動配置しない |

日本語だけでも読めるが、自動化の精度を上げるため、先頭にタグを書く。

良い例:

- `KEEP`
- `CUT｜脱線`
- `RESTORE｜サウナ復活`
- `MOVE_AFTER:NA12｜締めcouplet`
- `TRIM_TAIL:00:00:03:12｜尾の言い淀みだけ落とす`
- `NOTE: 繋がりが悪ければ#6サウナへ振替`

避けたい例:

- `詰め`
- `いい感じに`
- `要点だけ`
- `粒度はDaVinciで`
- `任意`
- `余裕があれば`

これらは人間向け備考としては問題ない。ただし、`編集指示` の主指示にすると自動反映は `SEMI` または `MANUAL` になる。

## 曖昧指示の書き換え

曖昧な指示は、タグと備考に分ける。

| 旧表現 | 推奨 |
| --- | --- |
| `詰め` | `TRIM_TAIL:<timecode>` または `KEEP` + `自動化レベル: SEMI` |
| `要点だけ詰め` | `KEEP` + `自動化レベル: SEMI` + `備考: 要点だけ使う` |
| `頭だけ残し｜尾半分カット` | `TRIM_TAIL:<timecode>` |
| `ラストへ移動` | `MOVE_AFTER:NA12` |
| `復活する残し` | `RESTORE` |
| `繋がり悪ければ落とす` | `RESTORE` + `優先度: B/C` + `備考` |
| `任意` | `RESTORE` + `優先度: C` |

迷う場合は、無理に精密化しない。`自動化レベル: SEMI` にして、Resolve上の確認対象として残す。

## ナレーション表

ナレーションWAVまで自動生成する場合は、発話表と別にNA表を作る。

| NA ID | 編集指示 | 本文 | 配置位置 | wav名 | 状態 | 備考 |
| --- | --- | --- | --- | --- | --- | --- |
| NA5 | NA_INSERT:NA5 | 国籍を、誰が、どう決めるのか... | AFTER:SEG06 | NA5.wav | GENERATE | ギア中→高 |
| NA8 | NA_INSERT:NA8 | 遠い国どうしを、いきなり... | AFTER:SEG13_LACRIS | NA8.wav | GENERATE | v2から位置移動 |
| NA12 | NA_INSERT:NA12 | サッカージャーナリストの木崎伸也と... | BEFORE:ENDING_COUPLET | NA12.wav | GENERATE | 固定 |

`状態` は以下を使う。

- `GENERATE`: WAVを生成する
- `EXISTS`: 既にWAVがある
- `RETAKE`: 再生成する
- `SKIP`: 今回は作らない

`配置位置` は、SEG ID、NA ID、または発話素材の移動先IDを使う。

例:

- `AFTER:SEG06`
- `BEFORE:SEG14`
- `AFTER:NA12`
- `BEFORE:ENDING_COUPLET`

## SEG本文の書き方

本文パートのSEG見出しは、人間向けの構成メモとして書く。

良い例:

```text
## SEG06｜#6 Caribbean｜00:16:52:08 → 00:21:15:15｜約3:30-4:00

目的: 中盤の息継ぎ。サウナ＆北欧雑談を復活。
採用方針: 静岡>ヘルシンキ、共用サウナ、戦争で電気代2倍を優先。
注意: つながりが悪ければ混浴ドイツは落とす。
```

この本文はIR生成の補助に使えるが、最終的な編集判断は表に落とす。

## 色分け台本とブロック荒編

初稿段階では、発話行ごとにフィラーまで厳密カットしすぎない。まずSEG/ブロック単位で使い所を抜き、色分けして、構造を確認する。

推奨順:

```text
収録書き起こし
→ 使い所をざっくり抜く
→ 台本でSEG色分け
→ block_color_plan生成
→ DaVinci上でSEG/ブロック単位に色分け
→ 聴感確認
→ 必要箇所だけ細かいカット
```

SEG見出しには、色名、元TC範囲、目安尺を書く。

例:

```text
## SEG06｜#6 Caribbean｜00:16:52:08 → 00:21:15:15｜約3:30-4:00
```

この形式なら、以下のコマンドでブロック色計画を作れる。

```bash
python3 scripts/platto_script_to_block_color_plan.py \
  /path/to/platto_script.pdf \
  --fps 24 \
  --out-json output/ep40/block_color_plan.json \
  --out-csv output/ep40/block_color_plan.csv \
  --out-report output/ep40/block_color_plan.md
```

色名はDaVinciのclip colorへ近い色に寄せる。

| 台本色 | Resolve色 |
| --- | --- |
| `Rose` | `Pink` |
| `Mango` | `Orange` |
| `Yellow` | `Yellow` |
| `Lavender` | `Violet` |
| `Caribbean` | `Teal` |
| `Tan` | `Tan` |
| `Forest` | `Green` |
| `Blue` | `Blue` |
| `Purple` | `Purple` |
| `Teal` | `Teal` |
| `Cerulean` | `Blue` |
| `Violet` | `Violet` |

この段階では「フィラーを全部切る」ことを目的にしない。目的は、どのブロックを使うか、復活候補をどの位置に戻すか、台本の色分けとタイムラインの見た目を合わせること。

## 優先度の使い方

復活候補や迷いがある行には `優先度` を付ける。

- `A`: ほぼ必ず残す。構造上重要。
- `B`: 尺が許せば残す。内容の厚み。
- `C`: 任意。尺調整用。

45分へ戻す場合は、`A` から順に採用する。短くしたい場合は、`C` から落とす。

## 初稿想定尺

DaVinciを触る前に、Doc/CSVだけで初稿の想定尺を確認する。

基本式:

```text
KEEP / RESTORE の元素材尺
+ NA の想定尺
+ 必要なら余白
= 初稿想定尺
```

この時点で目標尺から大きく外れている場合は、DaVinci上で直さず、Doc/CSVへ戻って編集指示を直す。

短い場合:

- 戻したい行を `RESTORE` にする
- `PRIORITY:A/B/C` または `優先度` を付ける
- まずA、足りなければB、最後にCを戻す

長い場合:

- 落としてよい行を `CUT_IF_OVER` にする
- 低優先度の `RESTORE` を `B` / `C` へ下げる
- 長いNAは本文を書き直すか `SHORTEN_NA` と備考に書く

例:

| 編集指示 | Speaker Name | イン点 | アウト点 | 文字起こし | 優先度 | 備考 |
| --- | --- | --- | --- | --- | --- | --- |
| RESTORE | 朴 | 00:18:44:03 | 00:19:24:03 | 各アパートに共用サウナ... | A | 短ければ必ず戻す |
| CUT_IF_OVER | 木崎 | 00:40:26:12 | 00:41:10:05 | 国家プロジェクトの追加例... | C | 長ければ落とす |
| KEEP | 朴 | 00:57:16:08 | 00:57:30:20 | 入管法以降は在留カードを... | B | 要点 |

尺を見るコマンド:

```bash
python3 scripts/doc_ir_duration_report.py \
  output/ep40/desired_timeline_ir.json \
  --target-minutes 45 \
  --out-json output/ep40/duration_report.json \
  --out-report output/ep40/duration_report.md \
  --out-csv output/ep40/duration_events.csv
```

NA WAVが生成済みなら `--na-dir output/ep40/na_wav` を足す。未生成なら文字数から仮尺を出す。

## 自動化レベル

`自動化レベル` は、機械にどこまで任せられるかを書く。

- `AUTO`: そのままResolveへ反映できる。
- `SEMI`: マーカーや候補配置まではできるが、人間確認が必要。
- `MANUAL`: 人間が判断する。自動配置しない。

例:

| 編集指示 | 自動化レベル | 理由 |
| --- | --- | --- |
| `KEEP` | `AUTO` | in/outが明確 |
| `RESTORE` | `AUTO` | in/outが明確 |
| `TRIM_TAIL:00:04:54:10` | `SEMI` | トリム境界の確認が必要 |
| `NOTE: 繋がりが悪ければ落とす` | `MANUAL` | 判断が必要 |

## Resolve反映の色

DocからResolveへマーカーを打つときは、以下の色を基本にする。

| action | Resolve marker |
| --- | --- |
| `SOURCE` | Yellow |
| `KEEP` | Green |
| `RESTORE` | Blue |
| `CUT` | Red |
| `MOVE` | Purple |
| `NA_INSERT` | Cyan |
| `NOTE` | Yellow |

未編集CSVや判断前の素材は `SOURCE` として黄色にする。

## EP40での推奨テンプレ

EP40のGoogle Docは、以下の順番にする。

1. タイトル、収録日、出演者
2. 今回の編集方針
3. SEG構成メモ
4. NA表
5. 発話素材の編集指示表
6. 人間向けメモ

機械が読むのは、原則として `NA表` と `発話素材の編集指示表` だけにする。

## 最低限の運用

急いでいる場合は、発話表の `編集指示` だけ整えればよい。

最低限これだけ:

- 残す行は `KEEP`
- 落とす行は `CUT`
- 復活候補は `RESTORE`
- 移動する行は `MOVE_AFTER:<ID>`
- 判断が必要な行は `NOTE:` または `自動化レベル: SEMI`

ナレーションを自動生成したい場合だけ、NA表を追加する。

## NGではないが自動化しにくいもの

以下は書いてよい。ただし表の主指示にはしない。

- 「粒度はDaVinciで」
- 「つながりが悪ければ」
- 「任意」
- 「余裕があれば」
- 「雰囲気で」
- 「いい感じに」

これらは `備考` に入れる。機械は備考を読んで候補分類まではできるが、完成形の自動配置判断には使わない。

## まとめ

Google Docは、自由な台本でありながら、表だけは少し硬く書く。

- 人間の判断は本文に書く。
- Resolveに反映したい判断は表に書く。
- `編集指示` はタグで始める。
- 曖昧さは `備考` に逃がす。
- ナレーションはNA表で管理する。

この形にすると、Docを更新するだけで、Resolve上のマーカー、残し/カット案、復活案、ナレーションWAV生成、ナレーション配置案まで段階的に自動化できる。
